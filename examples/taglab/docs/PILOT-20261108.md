# Small paired model run — 2026-11-08

This is a diagnostic run, not a benchmark or a strategy-selection result. Raw publisher text, individual human labels, credentials and full model dumps remain local.

## Setup

Ten pilot records were fixed by their existing ID order before seeing this run's outputs. Each received one A and one B request to the configured `qwen3.8-flash` model: 20 requests in total. A receives label IDs/names; B adds definitions, counterexamples and rules. Both use the same JSON and exact-quotation contract, temperature 0.2, output limit 1,200 tokens and disabled thinking mode. There were no automatic retries and no holdout requests.

Four records had references in the immutable run snapshot. These are single-user references; two had subsequently received assistant evidence review, which is not independent dual-human agreement. A later audit flagged one pre-existing reference label's supporting quotation for review. No reference or experiment score was edited after inspecting model outputs.

## Observed results

| Measure | A | B |
| --- | ---: | ---: |
| Structurally valid, continuous-quotation outputs | 9/10 | 9/10 |
| Rejected outputs | 1 | 1 |
| Valid outputs requesting review | 0 | 2 |
| Recorded total tokens | 8,160 | 14,265 |
| Mean request latency | 3.42 seconds | 3.47 seconds |
| Topic micro F1 against four snapshot references | 0.875 | 0.769 |
| Format agreement against four snapshot references | 4/4 | 3/4 |
| Complete topic-set and format agreement | 2/4 | 2/4 |

Invalid outputs count as end-to-end misses. Scores include valid predictions that request review, so they do not measure safe automatic publication. The reference set is tiny, category-skewed and contains a pending evidence question. **These scores do not establish that either strategy is better.** Tokens include rejected outputs and are not a cash bill. Calls always used A then B, so these latency observations are not a randomized performance comparison.

Among eight records where both outputs passed mechanical validation, five had different topic sets or formats. Disagreement identifies review targets; it does not identify which candidate is right.

## Failures and decisions

- B assembled quotations with ellipses. The validator rejected the output and retained the original rejected object, usage and error. It was not silently repaired and counted as success.
- A returned a monologue format with an empty quotation while its explanation said the format should be unknown. Actual fields, rather than an inferred repair of the explanation, determined validation failure.
- Two further B outputs used genuine quotations that did not establish speaker count. Both passed substring checks and did not request review. This demonstrates the distinction between quotation integrity and semantic support.
- A reference-evidence question was recorded separately instead of automatically treating both models' disagreement with that label as model error or changing the reference to improve scores.

The two semantic-support cases were exported to a separate live Argilla **review** dataset. SDK read-back verified two records, four machine Suggestions and zero human Responses. The browser showed the machine-candidate provenance and the separate semantic-support question. Review responses cannot be promoted through the blind-reference adjudication path.

No prompt or validator was relaxed to erase these errors, and the batch was not rerun until it looked better. The next work is reference adjudication and semantic review, then broader independent references before strategy selection. The local corpus still has seven accepted references; creating review tasks did not increase that count.

## Follow-up review and reference sensitivity

The user subsequently kept both monologue interpretations as disputed feedback rather than independent scoring references. Original responses and explanations were archived before recording the later explicit choice. One pasted quotation had boundary whitespace; the importer now trims it only if the trimmed quotation exactly matches input, retaining an audit of both values. It does not repair interior content or change model-output validation.

The user also explicitly removed one lifestyle label from an existing reference. A separate analysis reused the same saved predictions: A topic F1 changed from 0.875 to 0.933, B from 0.769 to 0.833, with four usable references in each calculation. Both complete-match counts changed from 2/4 to 3/4. The original experiment and exported snapshot hashes remained identical, and no model call was made. These changes came from a post-output reference revision; they are not evidence of a better model or a new blinded benchmark.

`workbench/reference_audit.py` checks input/taxonomy compatibility and creates an immutable analysis linked to its source run. The suite now has 40 passing tests, including exclusion of disputed references and rejection of model-visible feedback as independent references. The local corpus still has seven references and eight run records; reference analysis is stored separately rather than counted as a ninth model run.
